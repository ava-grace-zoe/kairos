# progress-manager 讨论记录

## 当前已确认决策

1. 统一入口：保存、更新和恢复都由 `progress-manager` 路由。
2. 进度根目录：按“用户显式路径 > 宿主项目/工作区根目录 > Git（分布式版本控制系统）工作树根目录 > 当前目录”解析。
3. 路径稳定性：每次 save 或 resume 只解析一次，后续始终使用锁定的绝对路径。
4. 路径可见性：首次扫描、读取或写入前，先显式告知用户本次 `.work-progress/` 绝对路径；操作后摘要再告知具体进度文件绝对路径。
5. 状态模型：`.work-progress/` 存放未完成任务，`.work-progress/archive/` 存放已完成任务；暂停、卡住和风险写入文件内容。
6. 兼容性：不自动迁移已经分散在子目录的旧 `.work-progress/`；用户显式给出旧路径时可继续读写。

## 决策记录

- 日期：2026-08-28
- 主题：进度文件路径不稳定
- 结论：取消“命令执行所在目录”契约，改为任务级进度根目录的优先级解析与单次锁定。
- 影响范围：`skills/progress-manager/` 的共享契约、save/resume 存储位置与输出，以及对应设计和入口文档。
- 后续动作：在多工作区宿主中补一次歧义选择实测；保留显式路径作为跨 Git 工作树迁移的恢复入口。

## 已废弃的旧决策

以下决策曾出现在旧文档中，但已被当前 Skill 实现取代：

1. 将进度保存到 `docs/progress/`。
2. 在文件名中使用 `doing|blocked|done` 状态后缀。
3. 状态变化时通过重命名文件更新状态。
