# progress-manager

统一保存、更新和恢复项目工作进度，并以任务级项目根目录稳定定位 `.work-progress/`。

## 概述

- 这个 skill 是什么：记录和恢复代码认知资产、执行计划、下一步和卡点的统一入口。
- 解决什么问题：使新会话无需重新探索代码库即可接手，并防止命令在 workspace（工作区）、Git（分布式版本控制系统）工作树、仓库根目录或子包之间切换时产生多个进度目录。
- 适用场景：保存进度、更新进度、恢复进度、继续上次工作或从断点接手。
- 不适用场景：项目正式文档、长期知识库、用户画像或多个 Git 工作树之间的自动进度合并。

运行时产物：

```text
<进度根目录>/.work-progress/
├── <任务标题>_<YYYYMMDDHHmm>.md
└── archive/
    └── <已完成任务>.md
```

## 工作流程

1. 输入与路由：从用户语义判断 save 或 resume；如用户给出进度文件、`.work-progress/` 目录或项目根目录，保留该路径作为根目录解析输入。
2. 解析进度根目录：
   - 优先级为“用户显式路径 > 宿主项目/工作区根目录 > Git 工作树根目录 > 当前目录”。
   - 显式项目根目录直接使用；`.work-progress/` 目录取父目录；进度文件向上定位 `.work-progress/` 后取其父目录。
   - 宿主同时提供 project root 与 workspace root 时优先 project root；多 workspace root 时按任务目标、当前目录和最深嵌套路径依次缩小候选。
   - 需要 Git 降级时运行 `git -C "<任务相关起点目录>" rev-parse --show-toplevel`。
   - 命令的输入是任务相关目录；成功输出是 Git 工作树根目录的绝对路径；失败且没有宿主根目录时才降级到当前目录。
3. 锁定并告知路径：本次操作只使用 `<进度根目录>/.work-progress/` 的绝对路径。首次扫描、读取、创建或更新前，先显式告知用户该路径，再直接继续；后续 `cd` 或子命令不触发重新解析。
4. save 处理：扫描未完成文件，按完整文件名、关键词和当前任务的顺序新建或更新；完成时移入 `archive/`。
5. resume 处理：扫描已锁定目录的未完成文件，确定唯一目标，按更新时间校验认知资产并输出恢复摘要。
6. 输出摘要：操作完成后，再告知用户实际读写的进度文件绝对路径、状态、下一步和必要风险。

失败处理：

- 用户显式路径不存在或缺少当前操作所需权限（save 需读写，resume 需读取）：输出该绝对路径并停止，不降级到当前目录。
- 多个宿主根目录都包含任务目标：列出候选绝对路径供用户选择，不同时扫描或写入多个目录。
- 已锁定的 `.work-progress/` 不存在：save 在该根目录下创建；resume 返回“无可恢复项”，不在其他子目录中递归搜索。

## 已知问题

1. 任务跨两个独立 Git 工作树迁移时，宿主项目根目录会变化。
   - 影响：新工作树不会自动发现原工作树中的进度文件。
   - 临时规避：恢复时显式给出原进度文件或根目录绝对路径。
   - 后续计划：根据实际使用需求评估是否增加可选共享存储，不默认跨工作树搜索。
2. 同一分钟内为同一标题新建多个进度文件时可能文件名冲突。
   - 影响：新建操作可能与已有文件重名。
   - 临时规避：新建前先扫描同名未完成任务，有明确相关文件时更新而非新建。
   - 后续计划：结合真实冲突案例决定是否将时间戳提升到秒级。
