# 冒烟验收回归案例

记录每次 subagent 冒烟验收的被测对象、场景、结果和发现，用于累计校准 references/ 中的检查清单。

## 案例 1：progress-manager 文档集（2026-07-03）

- **被测对象**：`skills/progress-manager/` 全部三个文件（SKILL.md、save-progress.md、resume-progress.md），原文内联。
- **执行方式**：按 `references/smoke-test.md` 第 2 节——Agent 工具 + `model: "haiku"` + prompt 工具禁令。结果有效性：subagent 工具调用数为 0（平台回执确认），隔离有效。
- **场景设计**：5 个业务目标场景，未使用"保存/恢复"等路由关键词。

### 逐场景结果

| 场景 | 结果 | 发现 |
|---|---|---|
| 1. 半途收工，固化现状供新会话接手 | 通过 | 目录创建、命名格式、模板九个区块、输出摘要全部正确推演 |
| 2. 新会话"接着上次的活儿干" | 通过 | 扫描 → 定位 → 按优先级加载 → 时效性校验 → 恢复摘要 → 等待指令，全流程正确 |
| 3. 用户告知某任务已完成 | 通过 | 关键词匹配 + 移入 `archive/` 正确；指出 archive/ 不存在时是否自动创建表述不够显眼（save-progress.md 状态变更第 4 条其实覆盖了，但位置离归档动作较远） |
| 4. 三个未完成任务，用户只说"继续" | **部分通过** | 最终结论正确（列候选供用户选择），但推演过程先发明了两层文档外启发式（按"进行中"状态优先、按时间戳自动取最新）。定位到根因：SKILL.md 匹配优先级第 3 条写"**自动选择**最后……自动新建、更新或恢复"，与 resume-progress.md"多候选时列出供用户选择、不要猜测"存在措辞张力，诱导读者在恢复路径上尝试自动选择 |
| 5. 从未记录过进度却说"从断点继续" | 通过 | 正确返回"无可恢复项"，未新建文件 |

### 判定与后续动作

- 按评估表，场景 4 属"推演出错误命令 → 文档存在歧义或误导性描述 → 重写相关段落"。
- 待办：修改 `skills/progress-manager/SKILL.md` 匹配优先级第 3 条措辞，把"自动选择"限定到保存路径（自动新建/更新），恢复路径显式改为"唯一未完成任务才直接恢复，否则列候选"。属 progress-manager 的变更，不在本次 agent-facing-design 改造范围内，单独处理。
- subagent 额外指出的边界缺口（同一分钟文件名冲突、进度文件格式破损时的降级策略），记为 progress-manager 的低优先级已知问题，暂不处理。

### 对本 skill 的校准反馈

- 隔离方案（文档内联 + prompt 禁令 + 低级模型）实测可行，平台回执的工具调用计数可作为结果有效性的客观证据——已优于原设计中"看回复措辞自查"的软判据，可在 smoke-test.md 后续版本中补充。
- 业务目标场景设计有效：场景 4 成功暴露了带路由关键词的场景测不出的措辞歧义。
