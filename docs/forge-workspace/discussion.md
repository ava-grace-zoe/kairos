# forge-workspace 讨论记录

## 智能体根入口

用户指出模板工程需要根目录 `AGENTS.md`，直接向编程智能体提供总览和重要规则。原模板已有该文件，但内容仅为简短约定，上一轮说明也没有将其明确为入口。现将其补齐为工程定位、目录职责、接手顺序、关键规则、常用命令和完成标准；详细规范通过 `docs/index.md` 与专题文档按需读取。模板的说明文件、文档导航和技能执行步骤同步明确这一关系。

## 当前决策状态

- 名称确定为 `forge-workspace`（工程铸造）。
- 用户指定的技术栈已实现；用户基本认可建议后，第一版采用 tsdown（TypeScript 共享包构建工具）、Vite（前端开发构建工具）、PostgreSQL（关系型数据库）、ECMAScript Modules（标准 JavaScript 模块格式）及 React Router Data Mode（带数据加载和提交的路由模式）。
- 模板、生成脚本与资源清单一起分发，历史版本恢复已用隔离 Git（版本控制工具）仓库验证。真实远端标签尚未发布。
- 当前具体版本、取舍及限制见 [design.md](design.md)，实际运行证据见 [validation.md](validation.md)。

## 模板位置与来源

日期：2026-09-28。

最初只说明模板在技能的 `assets/`，没有说明安装时如何获取、初始化如何读取，以及升级技能后旧项目如何扩展。用户追问“模板放在哪，初始化或者新增子项目从哪下载”，暴露了分发设计缺失。

修正后，资源源位置为 `skills/forge-workspace/`，安装时整体复制。初始化读取本地资源并缓存；新增按工作区记录的版本选择本地副本、缓存或精确发布标签。与独立模板仓库、独立生成器包相比，这减少了当前技能入口的发布关系，代价是资源体积与历史版本恢复逻辑。

实现后验证了安装文件完整性、旧项目配新技能时命中旧缓存、无缓存时下载准确标签，以及内容被修改时拒绝使用。未发布版本缺失时明确报错；真实远端仓库发布不属于已完成的验证。

## 命名与实现范围

日期：2026-09-28。

用户基本认可分发方案，但否定原来的技术描述名并要求重新命名、实际跑通。技能改为 `forge-workspace`，完成工作区创建、三种子项目扩展、文档规范、数据库和统一测试流程。

模板统一使用 `.tpl` 后缀，隐藏文件路径用 `__dot__` 编码，防止安装工具过滤配置和依赖清单。工作区版本与项目登记写入 `.forge/workspace.json`。

## 实测驱动的设计修正

- Biome（代码检查与格式化工具）需要开启参数装饰器解析；导入排序增加工作区作用域分组，避免工程名称变化导致初始化后检查失败。
- TypeScript 7 虽能构建，但 tsdown 提示接口支持仍属实验性，因此选用已验证的 6.0.3。
- 开发监听会清空共享包产物，与应用启动发生竞态；共享包监听改为保留已有构建产物。
- 后端监听限定到本工程产物，文件系统不支持原生监听时使用轮询；通过真实启动、源码修改及关闭服务验证，具体结果以验收记录为准。
