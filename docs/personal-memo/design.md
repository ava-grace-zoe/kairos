# personal-memo 设计文档

## 设计目标

让智能体拥有一个持久化的个人备忘录，能够记录、查找、整理和更新信息。用户只需要表达意图，标题、分类、记录粒度和检索策略交给模型判断。

技能提供存储约定与操作能力。它不把每次请求展开成固定审批、检查和确认流程，也不要求用户提前整理好数据。

范围：个人备忘录的增删改查、分类和时间检索。自动巡检、提醒和多端同步不在本版能力范围内。

## 方案概览

用户意图 → 模型结合内容与已有记录判断 → 调用 SQLite（嵌入式关系数据库）→ 返回有用的结果。

- 默认数据库：`$HOME/person.memo.db`，用户指定路径时采用指定值。
- 运行依赖：`sqlite3` CLI（Command-Line Interface，命令行界面）和系统 Shell（命令解释器）。
- `SKILL.md` 提供能力概览、数据模型和使用建议。
- `references/operations.md` 提供可组合的命令示例，按需要参考。
- `assets/schema.sql` 创建数据库；`assets/probe.sql` 用于能力诊断。
- macOS、Linux 的兼容 Shell 可以使用这些命令；已实测平台为 macOS。

## 关键取舍

1. **能力参考与固定流程**：采用能力参考。分类复用、去重、内容组织依赖语义判断，模型可以结合任务选择操作顺序。环境已知可用时，不要求重复做完整探测和结构审计。
2. **分类默认值与模型归类**：分类由内容决定；已有名称有助于保持一致，没有合适分类时自然建立新分类。去掉“未分类”默认值，也不把“先查分类”变成每次操作的强制步骤。
3. **单表与复杂模型**：一条记录一个文本分类，正文自由组织。足以支持当前需求，分类与内容可随实际使用调整。
4. **直接命令与包装程序**：使用官方命令行和 SQL（Structured Query Language，结构化查询语言），保持运行依赖简单；只详细说明引号、路径和时间等影响执行正确性的细节。
5. **文本搜索与全文索引**：SQLite 的 `instr()` 提供中文和特殊字符的字面子串匹配。模型可自行选择多个词、同义词和分次检索；数据库本身不提供语义匹配。

## 数据与接口

| 字段 | 含义 |
| --- | --- |
| `id` | 自增记录标识，删除后不复用 |
| `category` | 模型结合内容与已有分类选定的非空名称，无默认分类 |
| `title` | 方便辨认和查找的标题 |
| `body` | 自由文本，可使用 Markdown（纯文本标记格式） |
| `created_at` | 创建时间 |
| `updated_at` | 最后修改时间 |

时间存为 UTC（Coordinated Universal Time，协调世界时）的 `YYYY-MM-DDTHH:MM:SSZ`。按用户表达选择时间字段，并将用户时区中的起止点转换后查询。正文中的到期日期暂未独立建字段。

输入为用户的自然语言请求及可选路径。输出的详略、字段和条数由任务决定，查询可使用 JSON（JavaScript Object Notation，结构化文本交换格式）交给模型读取。

兼容性：结构版本仍为 `1`，字段与读写接口保持兼容。新库去掉分类默认值；旧库即使保留旧默认值也能使用，因为写入时模型会给出分类。已有记录和默认值不因技能更新自动改写。

## 风险与缓解

- 引号与多行内容可能破坏命令：提供可直接采用的多行输入和 SQL 转义示例。
- 普通打开命令会创建不存在的数据库：查询示例采用只读打开；初始化用于新文件。
- 复杂查询可能遗漏信息：模型根据结果调整词语、分类范围和输出大小；不将一次未命中等同于信息一定不存在。
- 多个写操作可能部分完成：可使用事务；错误与影响行数帮助判断结果。
- SQLite 文件默认不加密；存储和备份包含原始内容。
- 并发编辑同一条记录的自动合并、较大数据规模和其他平台尚未实测。
